# Claude Code Project Notes

## RL Training System

### Debugging

The RL training system has a global debug flag for verbose logging:

**Enable debug mode:**
```bash
# Via CLI flag (recommended)
npm run train -- --steps 100 --debug

# Via environment variable
RL_DEBUG=1 npm run train -- --steps 100
```

**Debug utility usage in code:**
```typescript
import { rlDebug, rlWarn, rlError, setRLDebug } from "./debug";

// Only logged when RL_DEBUG=1
rlDebug("BC", "My message", { optionalData: 123 });

// Always logged (warnings/errors)
rlWarn("BC", "Warning message");
rlError("BC", "Error message", error);

// Programmatically enable
setRLDebug(true);
```

**Key prefixes:**
- `BC` - BattleController (phase handling, action execution)
- `TRAIN` - Trainer (main training loop)
- `AGENT` - PPO Agent (model updates)

### Known Issues

1. **Phase timeouts (500ms)** - Some phases (SwitchSummonPhase, NextEncounterPhase) don't complete via callback in headless mode and timeout after 500ms. This is handled gracefully but limits training speed to ~3 SPS.

2. **Texture warnings** - "Texture not found" warnings are cosmetic and don't affect training.

### Episode Completion

The `battleWonThisStep` flag in BattleController tracks victories:
- Set when VictoryPhase or BattleEndPhase executes
- Used for episode termination in single_battle mode
- Used for win rate calculation in StepInfo

This is necessary because by the time `step()` returns, the game has already transitioned to the next battle (new enemies spawned), so `isEnemyDefeated()` would return false.

### Architecture

- `src/rl/battle-controller.ts` - Core RL controller, handles 4 decision types (COMMAND, CHECK_SWITCH, SWITCH, TARGET)
- `src/rl/training/trainer.ts` - Main training loop
- `src/rl/training/model.ts` - PPO agent implementation
- `src/rl/headless.ts` - Headless game initialization
